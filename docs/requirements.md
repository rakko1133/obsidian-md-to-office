### フェーズ 1 の決定事項（2026-11-18）

ユーザー決定
- Mermaid 画像のキャッシュ: 出力とは別の専用キャッシュを、プラグインのデータフォルダ（`.obsidian/plugins/batch-office-export/cache/mermaid/`）に持つ。画像ファイルを保存しない設定でも差分レンダリング（R4）が効く。上限 100 MB を超えたら古いものから消す（R4 と R8 の矛盾を解消）
- 保存モードの既定値: ミラー出力（R1・R8）
- 同名ファイルの既定の扱い: 上書き（R3）
- 右クリックや「現在のノートを変換」で直接選んだノートには glob の除外を適用しない。frontmatter の `export: false` は直接選んでも除外する（R2）

Claude 推奨（ユーザー承認）
- R1 の単独保存: 「Mermaid 画像として保存」を R2 の起動方法（ファイル・フォルダ・複数選択の右クリック、コマンド「現在のノート」「Vault 全体」）から呼べるようにし、01→02→03→06→09→10 の同じ流れを通す。画像はそのノートの出力先フォルダ（ミラー出力なら出力ルートの下の、元と同じフォルダ構成）に置く
- 構文解析: フェーズ 1 から remark（`remark-parse`）で mdast を作り、Mermaid のコードブロックを取り出す（G2）
- 既定値: エラー時の方針は continue-on-error、画像の形式は PNG、除外パターンは `**/*.excalidraw.md`
- `export: false` の値: 真偽値の `false` と文字列の `"false"` / `"no"` を除外として扱う
- 対象が 0 件なら確認画面を出さずに Notice で知らせる。チェックが 0 件なら実行ボタンを押せない
- ドライラン: 出力パスと予定動作を計算する純粋関数を、確認画面と書き込みで共用する。書き込み時に状況が変わっていたら、その時点の状態で判定してレポートに記録する
- 書き込み: Node.js の `fs` で、一時ファイル（`.{名前}.tmp`）に書いてから `rename` で置き換える。一時ファイルは書き込みの処理が `finally` で必ず消す。拡張子 `.md`・`.canvas` のファイルと今回の変換元には書き込まない。将来のモバイル対応に備えて、書き込みはアダプタに分ける
- 同じ名前の画像: ファイル名にハッシュが入るので、同じ名前なら同じ内容とみなし、書き込まずに「変更なし」とする
- 古い画像の削除: 削除する画像は Mermaid の画像化の処理がマニフェストの写しから決め、削除は書き込みの処理が行う。新しい画像を書き終えた後に消す。マニフェストに記録のないファイルには触れない
- マニフェスト: 形式のバージョン・出力パス・元ノート（配列）・種類・図の連番・内容ハッシュ・日時を記録する。壊れていたら空として扱い、元のファイルを `.broken` として退避して警告する。中断したときも、書き込んだ分は記録する
- 警告: 各処理が結果と一緒に返し、1 件ずつ順に変換する処理がノートごとにまとめる
- 結果レポート: モーダルで件数を表示し、明細は種類ごとに折りたためるようにする
- PNG 化に失敗したとき（tainted canvas）: SVG だけを保存して警告する
- 利用者が書いた `%%{init}%%`: テーマ・フォント・`htmlLabels` はプラグインの値で上書きし、それ以外は残す
- mermaid.js のバージョン: `mermaid.version` を使い、取れなければ Obsidian のバージョンで代用する

### フェーズ 3 の決定事項（2026-11-18）

ユーザー決定
- フェーズ 3 を 2 段に分ける。3a（タグ `0.3.0`）は内部リンク・ブロック ID・ノート埋め込み・画像・PDF 等・コールアウト・コードの色付け・脚注・コメント・frontmatter・インライン HTML と改ページ。3b（タグ `0.3.1`）は数式・Dataview・他プラグインのコードブロック・HTML → hast → mdast の取り込み・外部画像のダウンロード・コールアウトのテーマ色
- Wikilink・コールアウトは変換の段（G2 の transform）で扱う。構文解析は remark の標準の拡張だけにし、micromark 拡張は自作しない（A-0a の記述をこれに合わせて直す）
- 埋め込んだノートの見出しは、元のレベルのままにする

Claude 推奨（ユーザー承認）
- 内部リンク（A-18）: リンク先は `getFirstLinkpathDest` で解決する。変換対象（今回の対象 + マニフェストに .docx として記録されたノート）なら出力した .docx への相対リンク、対象外なら表示テキストだけ、リンク切れはテキストだけ残して警告する。`[[別ノート#見出し]]` はファイルへのリンクにする（見出しまで飛ぶのは結合出力のフェーズ 5）
- 同じノートの中へのリンク（A-19）: `[[#見出し]]` と `[[#^id]]` は文書内のブックマークへのリンクにする。`^id` は本文から消し、その段落にブックマークを付ける。ブックマーク名は見出しが `h_{連番}`、ブロックが `b_{id を英数字と _ にしたもの}`（40 文字以内）
- ノートの埋め込み（A-21）: 同じ変換をかけて取り込む。`#見出し` はその節、`#^id` はそのブロックだけ。循環参照を検出し、深さの上限は 5（固定）
- 画像（A-20）: バイト列は Obsidian 側で読んで .docx の生成へ渡す。Word が対応しない形式（WebP・GIF など）は canvas で PNG にし、SVG 画像には PNG フォールバックを付ける。`|300`・`|300x200` を反映し、指定がなければ本文の領域に収める。外部 URL の画像はリンクだけ
- PDF・音声・動画（A-22）は `obsidian://open` のリンク。Canvas の埋め込みは原文のまま残して警告する。Excalidraw は同じフォルダに書き出し済みの .svg / .png があれば使い、なければ原文のまま残して警告する（A-23）
- コールアウト（A-6）: 1 行 1 列の表。色は既定色の固定の表（テーマの色は 3b）。折りたたみは常に展開し、入れ子は表の入れ子
- コードの色付け（A-7）: Obsidian 同梱の Prism で Obsidian 側がトークンに分け、.docx の生成が固定の配色で色を付ける。言語が分からなければ等幅のまま。行番号はオプション（既定オフ）

  - PNG 化は `HTMLCanvasElement` へ `drawImage()` → `toBlob('image/png')`
  - HTML ラベル（`<foreignObject>`）を含む SVG は canvas が tainted になり `SecurityError` の可能性 → `htmlLabels: false` で回避を検討
  - Obsidian 本体の表示を変えない（評価で追記）: `loadMermaid()` で得る mermaid.js は Obsidian のプレビューと共有している。`mermaid.initialize()` でテーマ・`htmlLabels`・`fontFamily` を書き換えると、ユーザーのプレビュー表示まで変わってしまう。そのため、設定は図ごとにソースの先頭へ `%%{init: {...}}%%` ディレクティブを付けて渡し、グローバル設定には触れない。ディレクティブで渡せない設定がある場合だけ、変換前の設定を保存して変換後に必ず元に戻す（例外時も `finally` で戻す）
  - 図の種類によっては `htmlLabels: false` が効かないものがある可能性 → 全図種のサンプル（G5）で PNG 化できるか確認する

## R3. 安全な運用（確定・MVP）

### 実行前
- ドライラン: 書き込まずに「入力ノート → 出力パス」と予定動作（新規 / 上書き / スキップ / 連番）を一覧表示。R2 の対象確認モーダルに統合する

### 書き込み時
- 元ノートは書き換えない（設計原則）: .md・画像・.canvas は読み取り専用とし、書き込み系 API を呼ばない
- 同名ファイルの扱い: 上書き / スキップ / 連番（`name (1).docx`）を設定で選択
- アトミック書き込み: 一時ファイル（`.tmp`）に書き、完成後に rename で置き換える。失敗時に壊れた .docx / .xlsx を残さない
  - 一時ファイルの名前（評価で追記）: ドットで始める（`.{ファイル名}.tmp`）。Obsidian はドットで始まるファイルを索引の対象にしないので、書き込み中にファイルエクスプローラーに表示されない
- 使用中ファイルの扱い: Word / Excel で開いているファイルへの書き込み失敗（Windows の `EBUSY` / `EPERM`）は、中断せずスキップしてレポートに記録
- 個人情報を出力に含めない（設計原則、2026-11-17 に後回しから格上げ）: 文書プロパティ（作成者・最終更新者）や埋め込むパスに、OS のユーザー名や Vault の絶対パスを入れない（C-8・D-5）

### 実行中
- 進捗表示: 「n / 全体件数」と処理中ファイル名を Notice またはステータスバーに表示
- エラー時の方針: continue-on-error（失敗しても次へ）/ fail-fast（その時点で停止）を設定で選択
- UI を固めない（2026-11-17 に後回しから MVP へ移動）: 1件ずつ逐次処理し、件ごとに `await` でイベントループへ制御を返す。一括変換が目標の中心で、Mermaid の描画に DOM を使うため
- キャンセル（同上で MVP へ移動）: 進捗表示に中断ボタンを置く。処理中の1件を終えてから止め、書きかけの一時ファイルを削除する
  - 範囲（ユーザー決定・2026-11-17）: 処理中の1件は書き込みまで最後まで処理する。中断ボタンは「次の1件を始めない」だけで、処理中の件の描画や書き込みは打ち切らない。処理中の件を途中で打ち切るのは、下のタイムアウトのときだけ
- 1件ごとのタイムアウト（同上で MVP へ移動）: `mermaid.render()` などのハング対策。既定 30 秒、超えたらその件を失敗として次へ進む
  - 限界（評価で追記）: タイムアウトは `Promise.race` で実装するため、打ち切れるのは非同期の待ち時間だけ。メインスレッドを占有し続ける同期処理（無限ループなど）は打ち切れず、その間は UI も固まる。タイムアウト後も裏で処理が続く場合は、その結果を捨てる
  - 打ち切りの伝え方（ユーザー決定・2026-11-17）: `AbortSignal` に統一する。ノート1件ごとに `AbortController` を作り、その `signal` を構文解析・描画・生成・書き込みの各処理に引数で渡す。タイムアウトしたら `abort()` し、受け取った側は描画の依頼や書き込み（rename）の前に `signal.aborted` を確かめる。中断ボタンでは `abort()` しない
- 1件の結果の単位（ユーザー決定・2026-11-17）: 書き込みの結果は出力ファイル1つごとに返し（出力パス・内容ハッシュ・状態）、それをノートごとにまとめる。ノートの状態は、そのノートの出力のうちいちばん重いもの（失敗 > スキップ > 成功）。複数のノートを束ねた出力（ブック・結合 .docx）の結果は、そのグループの全ノートに付ける
  - 内容ハッシュは、出力のバイト列を持つ書き込みの処理で計算する

### 実行後
- 結果レポート: 成功・失敗・スキップ件数、未対応記法・リンク切れの警告を一覧表示
  - 件数の数え方（ユーザー決定・2026-11-17）: ノートの数で数える（進捗表示の「n / 全体件数」とそろえる）。出力ファイルごとの内訳は明細で見られるようにする。「表なし」は理由付きのスキップとして数える
- 出力マニフェスト: 生成ファイルの一覧（出力パス・元ノート・内容ハッシュ・日時）を JSON で保存。後回し項目（手編集の検知、Undo、孤立ファイル掃除）や R2 の差分変換の土台にする
  - 読み書きの時点（ユーザー決定・2026-11-17）: 実行の開始時に1回だけ読み込み、読み取り専用の写し（スナップショット）を実行中の処理（A-18 のリンク先の判定、R4 の古い画像の検索）に渡す。更新と保存は実行の最後に1回だけ行う。実行の途中ではファイルを読み書きしない
  - 保存場所（評価で追記・Claude 推奨）: プラグインのデータフォルダ（`{Vault}/.obsidian/plugins/batch-office-export/export-manifest.json`）。ファイル名を `manifest.json` にしないのは、同じフォルダにある Obsidian のプラグイン定義ファイル `manifest.json` と衝突するため。パスは Vault 内の相対パス、Vault 外の出力は出力ルートからの相対パスで記録し、Vault を移しても使えるようにする。Vault 内の出力フォルダに置かないのは、同期の対象やファイルエクスプローラーの表示に混ざるのを避けるため

## R4. 画像の出力（確定）

R1 で生成する Mermaid 画像の品質と、Word への埋め込み方法を決める。

- ラスタ解像度（PNG）: DPI で指定する（既定 192 dpi = 2x 相当。印刷用プリセットでは 300 dpi）
  - `canvas` の幅と高さを `DPI / 96` 倍にして描画する
  - PNG の `pHYs` チャンクに解像度を書き込み、Word で開いたときの実寸を合わせる
- Word に貼るときのサイズ: 本文幅に収める
  - 本文幅 = 用紙幅 − 左右の余白（A4・余白 25mm なら約 16cm）。これより大きい図は縦横比を保ったまま縮小する
  - 最大高さも制限する（縦に長いシーケンス図への対策）
  - 小さい図は拡大しない
- Word への埋め込み形式: SVG ＋ PNG フォールバック
  - Word 2016 以降は SVG を表示し、古い環境ではフォールバックの PNG を表示する（`docx` ライブラリの `type: "svg"` + `fallback`）
  - 要検証: Word の中で SVG のテキストがどう描画されるか（フォントの代替）
- 配色: Mermaid テーマは `neutral` に固定し、背景は白で塗る
  - Obsidian の表示テーマ（ダーク等）には追従しない
  - 背景の透過は PNG だけで選べるオプションにする
- フォント: `fontFamily` を設定で指定する。既定は Windows と Mac の両方にある組み合わせ（例: `"Yu Gothic", "YuGothic", "Hiragino Sans", "Meiryo", sans-serif`）
- ファイル名とキャッシュ
  - 命名規則: 連番とハッシュを併用する `{ノート名}_mermaid_{連番2桁}_{ハッシュ8桁}.{svg|png}`
  - ハッシュ: SHA-256 の先頭8桁。入力は Mermaid ソースに加えて、描画結果を変える設定値（テーマ・フォント・DPI・背景）と mermaid.js のバージョン（2026-11-17 整理で追加: ソースだけだと設定変更後も古い画像が使い回されるため）
  - 差分レンダリング: 同じハッシュの画像が既にあれば描き直さずに使う
  - 古い画像の置き換え（評価で追記）: 図を編集するとハッシュが変わり、古い画像が溜まっていく。そのため、新しい画像を保存するときは、出力マニフェスト（R3）に同じノート・同じ連番として記録された古い画像を削除する（マニフェストにないファイルには触れない）。ノートから図そのものが消えた場合の削除は、後回しの「孤立画像の削除」のまま
- 描画に失敗したとき: Word には Mermaid ソースをコードブロックとしてそのまま挿入し、結果レポート（R3）にも記録する
- キャプションと代替テキスト（設定で有効化、既定はオフ）
  - 図番号キャプション「図 n: ○○」。Word のキャプション機能（`SEQ` フィールド）を使い、図表目次も作れるようにする
  - キャプションの出どころ: Mermaid の frontmatter の `title`、なければ直前の見出し
  - 代替テキスト（alt text）: タイトル、なければ図の種類から自動で作る
  - 整理メモ: 図表番号は R4 のこの仕組みに一本化する（旧 C-4b・旧 H5 を統合）。表への「表 n」とすべての画像への適用は R6 の C-4b

- [ ] 孤立画像の削除: ノートから消えた図の画像を削除する

## R5. ノート内の要素の変換（確定・2026-11-17）

旧「候補A」。各論点の推奨案で確定。中間表現の設計は G2、画像の解像度・フォールバック・命名は R4、Word 全体の体裁（スタイル・ページ設定・フォント）は R6、Excel 全体の体裁は R7 に従う。

### 前提
- A-0a 変換方式: ハイブリッド。文書構造は Markdown の構文木（mdast: remark の標準の拡張で GFM・frontmatter に対応し、Wikilink・コールアウト・ブロック ID などの Obsidian 独自の記法は変換の段で mdast の独自ノードにする。2026-11-18 フェーズ 3 のユーザー決定で修正）から生成し、Dataview・数式・他プラグインのコードブロックだけ Obsidian 側（`MarkdownRenderer.render()` など）で描画して取り込む
- A-0b 未対応・変換失敗: 原文を等幅のまま残し、結果レポートに警告を出す

### Word: ブロック要素
- A-1 見出し: 組み込みスタイル「見出し 1〜6」（`w:pStyle`）に1対1で対応させる。オプション: レベルを1段下げてファイル名を「表題」にする / 見出し番号を複数レベルのリスト（`w:numPr`）で付ける
- A-2 単一改行: Obsidian の「厳密な改行」設定に従う（オフなら段落内改行 `w:br`）
  - 評価で追記: この設定値は非公開 API（`app.vault.getConfig('strictLineBreaks')`）でしか読めない。読めなかったときは、プラグインの設定画面での手動指定に従う（既定は Obsidian と同じ「オフ」）
- A-3 リスト: Word の段落番号機能（`numbering.xml` の `w:abstractNum`、入れ子は `w:ilvl`）を使う。開始番号（`3.` 始まり）とリストごとの番号リセットに対応する
- A-4 タスク: 記号 ☐（U+2610）/ ☑（U+2611）。`[/]` `[-]` `[>]` などのカスタム状態は記号の対応表で変換する
- A-5 引用: 組み込みスタイル「引用文」
- A-6 コールアウト: 1行1列の表。左罫線を種類の色、背景を淡い色（`w:shd`）にし、先頭行に種類名とタイトルを置く。折りたたみ（`[!note]-`）は常に展開し、入れ子は表の入れ子にする。色は「既定色の固定表 / テーマの `--callout-color` を読む」を設定で選ぶ
- A-7 コードブロック: Prism（`loadPrism()`）でトークン化してシンタックスハイライトを付ける（`w:color`）。言語が不明なら等幅フォント＋網掛け。オプション: 行番号
- A-8 水平線 `---`: 段落の下罫線。`<div style="page-break-after: always"></div>` は改ページ（`w:br w:type="page"`）として扱う
- A-9 表: Word の表。見出し行を各ページで繰り返し（`w:tblHeader`）、列の揃え（`w:jc`）、セル内の書式と `<br>` を保持する。列幅は自動調整。罫線・網掛けは R6 の C-6
- A-10 脚注（`[^1]`、インライン脚注 `^[...]`）: Word の脚注（`w:footnoteReference`）
- A-11 数式（`$...$` / `$$...$$`）: Word のネイティブ数式（OMML: `m:oMath` / `m:oMathPara`）。LaTeX → MathML → OMML と変換する（要検証）。変換に失敗した式は MathJax の SVG 出力で画像化する
  - 2026-11-18 フェーズ 3b のユーザー決定で更新: MathML を経由せず、docx ライブラリの `latexToMath` で LaTeX → OMML に直接変換する（下の「評価で更新」の経路は使わない）。構文解析は `remark-math`
  - 評価で更新: LaTeX → MathML は Obsidian 同梱の MathJax（`loadMathJax()`）を第一候補にし、依存を増やさない（だめなら Temml、MIT）。MathML → OMML は `mathml2omml` がライセンス（LGPL）で使えないため、MIT 等のライブラリを探すか、主要な要素（分数・上付き下付き・根号・行列など）に絞って自作する。めどが立たなければ、その時点でユーザーに相談する（代わりの案: 数式は画像化のみで v1 に入れ、OMML 化は後回し）
- A-12 Mermaid: R1 のとおり画像で埋め込む。SVG を PNG の代替画像付き（`a:blip` + `asvg:svgBlip`）で埋め込む（要検証）

### Word: インライン要素
- A-13 文字書式: 太字 → `w:b`、斜体 → `w:i`、取り消し線 → `w:strike`、`==ハイライト==` → `w:highlight`（黄）、インラインコード → 等幅＋網掛けの文字スタイル
- A-14 インライン HTML: `<u>` `<sup>` `<sub>` `<mark>` `<br>` は対応する書式にし、それ以外のタグは除去してテキストだけ残す
- A-15 タグ `#tag`: テキストのまま残す
- A-16 コメント `%%…%%`: 削除する。オプション: Word のコメント（`w:comment`）として残す

### Word: リンク・埋め込み
- A-17 外部リンク・URL 直書き: ハイパーリンク（`w:hyperlink`）
- A-18 内部リンク（Wikilink・見出しリンク・別名付きリンク・`[text](note.md)`）: 単体出力では出力先 .docx への相対リンクにし、リンク先が変換対象外なら表示テキストのみにする。結合出力（C-8、ユーザー決定で v1 に採用）では文書内ブックマーク（`w:bookmarkStart` + `w:hyperlink w:anchor`）へのリンクにする。リンク切れはテキストのみ残してレポートで警告する。リンク先は `metadataCache.getFirstLinkpathDest()` で解決する

- A-21 ノート埋め込み `![[ノート]]`: 内容を展開する（トランスクルージョン）。`#見出し` の指定はその節だけ、`#^id` の指定はそのブロックだけを取り込む。循環参照を検出し、展開の深さに上限（例: 5）を設ける

## R7. Excel の出力の質（確定・2026-11-17）

### D-1. シートの割り当て
- D-1a 1表 = 1シート: A-31 のオプションとして残す（既定ではない）
- D-1b 1ノート = 1シート（ユーザー決定・既定）: ノート内の表を縦に並べ、表と表の間は空行で区切り、直前の見出しを表題として置く（A-31）。表が1つもないノートはシートを作らず、レポートに「表なし」と記録する（A-30 でアウトライン形式を選んだときは作る）

### D-2. 値の型の判定
- v1: 判定は列単位。見出し行を除く列のすべてのセルが同じ型として読めるときだけ、その型に変換する（1セルでも読めなければ列全体を文字列のままにする）
  - 空のセル（評価で追記）: 型の判定から除外し、空のセルのまま書き込む。列のセルがすべて空なら文字列の列とする
  - 日付として認識する書式（評価で追記）: `YYYY-MM-DD`・`YYYY/MM/DD`（後ろに `HH:mm` が付いてもよい）だけ。`11/17` のように年がないものや、月日の順が曖昧なものは文字列のままにする
- v1: 判定する型は数値・日付・真偽値・パーセント（`12%`）・通貨（`¥1,200`）。セルの表示形式（number format）も合わせて設定する
- v1: 文字列のままにする例外: 先頭がゼロの値（`00123`）、郵便番号・電話番号の形、16桁を超える数字（Excel の数値の有効桁数は15桁なので精度が落ちる）
- v1: `=` `+` `-` `@` で始まる文字列は文字列として書き込む（数式インジェクション対策）
  - 評価で追記: .xlsx では、文字列型で書き込んだセルは数式として評価されないので、exceljs に文字列として渡せば対策になる（数値・数式として渡さないことをテストで確認する）。値をそのまま書き出すと危険なのは CSV で、そちらの対策は H1 の CSV に記載
- [ ] 後回し: 数式として評価することを設定で許可する（H5 の「数式の保持」と一緒に作る）

- v1（既定オン）: 各表を Excel テーブル（ListObject、exceljs の `addTable()`）として出力する。縞模様の行・フィルター・構造化参照がまとめて付く。1シートに複数の表を縦に並べても、表ごとに別のテーブルになる

- v1: Markdown の配置指定を、セルの水平方向の配置に反映する

- 書式・リンク・`<br>`: A-32 に統合
- v1: セルに入る文字数の上限（32,767文字）を超えたら切り詰めて、レポートで警告する
