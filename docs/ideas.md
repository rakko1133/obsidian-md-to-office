## G. 設計の前提（確定）

### G1. 公開範囲（確定 2026-11-17）
- 最初から Obsidian 公式 Community Plugins への掲載を目標にする
- 帰結
  - Obsidian の開発者ポリシー・プラグインガイドラインに従う（Node.js / Electron API を使うなら `isDesktopOnly: true`、ネットワーク通信の明示、`innerHTML` の安易な使用を避ける 等）
  - 依存ライブラリはライセンスが再配布可能なもの（MIT / Apache-2.0 等）に限る
  - README・LICENSE・`manifest.json`・`versions.json`、GitHub Releases での配布（`main.js` / `manifest.json` / `styles.css`）を v1 の範囲に含める

### G2. 中間表現（AST）を挟む設計（確定 2026-11-17）
- 変換処理を「構文解析 → 変換 → 出力」の3段に分け、間に中間表現として mdast（unified / remark の Markdown 構文木）を挟む
  1. 構文解析（parse）: .md → mdast（`remark-parse`、表・脚注・タスクは `remark-gfm`、frontmatter は `remark-frontmatter`、数式は `remark-math`）
  2. 変換（transform）: Obsidian 独自記法（Wikilink、埋め込み、コールアウト、`==ハイライト==`、`%%コメント%%`、Mermaid コードブロック など）を、独自ノード型として mdast 上で扱う
  3. 出力（render）: mdast → 出力形式ごとのレンダラ（.docx レンダラ、.xlsx レンダラ）
- 変換段は「変換処理の配列」として組み、処理を1つずつ足せる形にする（H3 の拡張性に備える）
- 帰結
  - 出力形式の追加（H1 の PDF / pptx / HTML など）は、レンダラを1つ足すだけで済む
  - 独自記法への対応（H3）は、変換段に処理を1つ足す形で追加できる
  - 構文解析と変換の段は Obsidian API に依存させない → 単体テストが書きやすく、CLI 版（H4）にも流用できる
  - unified / remark 系は MIT ライセンスで、G1 の再配布条件を満たす
- 実装メモ（要検証）
  - Obsidian 独自記法のうち、既存の remark プラグインで足りるものと自作が必要なものの洗い出し
  - バンドルサイズ（esbuild でまとめた `main.js` の大きさ）

### G3. 変換エンジン（確定 2026-11-17）
- 方式: 純 JS ライブラリのみで生成する。Pandoc などの外部ツールには依存しない（プラグインを入れるだけで動く）
- .docx: `docx`（MIT）。G2 の .docx レンダラが mdast → `docx` のオブジェクトに変換する
- .xlsx: `exceljs`（MIT）。書式・罫線・ウィンドウ枠の固定・オートフィルタ・数式・画像に対応（R7 に対応可能）
- 帰結
  - Obsidian 独自記法の解釈は自前で行う（G2 の変換段で扱う）
  - `exceljs` によりバンドルが数百 KB 増える。サイズは許容し、必要なら後で対策を検討（G2 の実装メモ「バンドルサイズ」と合わせて確認）
  - 外部プロセス（`child_process`）を使わないため、G3 単体ではモバイル対応の妨げにならない

### G4. v1 はデスクトップ専用（確定 2026-11-17）
- `manifest.json` に `isDesktopOnly: true` を設定する
- 帰結
  - Vault 外へのミラー出力（R1・R8）に Node.js の `fs` を使える
  - ただし構文解析・変換・出力の中核（G2）は Node.js / Electron API に依存させない。ファイルの読み書きは出力先アダプタに分離し、後からモバイル対応を追加できる余地を残す
- 出力先の範囲: Vault 内のフォルダ、または Vault 外の絶対パスを選べる。既定値は Vault 内の出力フォルダ（保存モードとの関係は R8）
  - Vault 内に出すと、生成物がファイルエクスプローラーに表示され、Obsidian Sync やクラウド同期の対象にもなる（設定画面で注意書きを出す）
  - Vault 外出力はデスクトップ限定の機能として出力先アダプタ側に閉じ込める
- [ ] 将来の候補: モバイル対応（出力先は Vault 内のみ、`Platform.isDesktop` で分岐）
- 実装メモ（要検証）
  - `exceljs` のブラウザ向けビルドが Electron のレンダラプロセスで動くか（G3 と合わせて、最初の .xlsx 実装時に確認）

### G5. 開発と検証の前提（確定 2026-11-17・Claude 推奨）
- 言語とビルド: TypeScript + esbuild（Obsidian 公式のサンプルプラグインの構成に合わせる）
- 単体テスト: Vitest。G2 の構文解析・変換の段を、Obsidian を起動せずにテストする
- テスト用 Vault: 各記法のサンプルノート（R5 の A-1〜A-34 を1つずつ含む）と、Mermaid の全図種のサンプルを用意する。各フェーズの動作確認に使う
- 対応する Obsidian の最小バージョン（`minAppVersion`）: 開発開始時点の最新の安定版に合わせる
- 依存ライブラリのライセンス確認（G1 の条件）: `docx`、`exceljs`、unified / remark 系、`picomatch`、Temml または MathJax、`mathml2omml` など。新しく依存を足すたびに確認する
- Obsidian に同梱されたライブラリ（mermaid.js、MathJax、Prism）は、Obsidian の更新でバージョンが変わる前提で作る（R4 のキャッシュ判定にバージョンを含める）

## R1. Mermaid 図を画像にして保存（確定）

- 対象: Mermaid の全図種（フローチャート、シーケンス図、クラス図、状態遷移図、ER 図、ガントチャート、円グラフ、マインドマップ など）
- 出力形式: SVG / PNG / 両方 を設定で選択
  - 整理メモ: この設定は「画像ファイルとして保存する形式」だけに効く。Word への埋め込みは常に SVG ＋ PNG フォールバック（R4）、Excel への貼り付けは常に PNG（A-33）
- 保存モード（設定で選択）
  - ミラー出力モード: 変換元と同じフォルダ構成を別の出力先に再現して保存
  - 同一フォルダモード: 変換元 .md と同じフォルダに保存
  - 整理メモ: 保存モードは画像だけでなく、.docx / .xlsx を含むすべての出力に共通で効く（R8）
- Word 変換時: Mermaid 部分を画像として .docx に埋め込む
- 実装メモ（要検証）
  - `loadMermaid()`（Obsidian API）で同梱 mermaid.js を取得し、`mermaid.render()` で SVG を生成
  - PNG 化は `HTMLCanvasElement` へ `drawImage()` → `toBlob('image/png')`
  - HTML ラベル（`<foreignObject>`）を含む SVG は canvas が tainted になり `SecurityError` の可能性 → `htmlLabels: false` で回避を検討

## R2. 変換対象の選び方（確定・MVP）

- 起動方法
  - ファイルエクスプローラの右クリック（ファイル / フォルダ）: `workspace.on('file-menu')`
  - 複数選択したファイルの右クリック: `workspace.on('files-menu')`
  - コマンド「現在のノートを変換」: `addCommand()` + `workspace.getActiveFile()`
  - コマンド「Vault 全体を変換」: `vault.getMarkdownFiles()`
- 対象範囲: フォルダ指定時はサブフォルダまで再帰的に含める
- 除外
  - glob パターンの include / exclude（例: exclude `Templates/**`、`*.excalidraw.md`）。`picomatch` などを使用
  - frontmatter の `export: false` で個別に除外（既定は「含める」= オプトアウト方式）。`metadataCache.getFileCache(file).frontmatter` で判定
  - 整理メモ: 非公開ノートの除外（旧 R3 後回し・旧 H6「機密情報の除外」）は、この `export: false` で対応する。`#private` タグなどでの除外は、下の「タグや frontmatter の値で絞り込み」に統合する
- 対象確認モーダル: 実行前に、対象ノートをチェックボックス付きツリーで表示し、件数と出力先を確認してから実行する（R3 のドライランを兼ねる）。出力形式（Word / Excel / 両方）と、結合出力をするかどうかもここで選ぶ（R8・C-8）

## R3. 安全な運用（確定・MVP）

### 実行前
- ドライラン: 書き込まずに「入力ノート → 出力パス」と予定動作（新規 / 上書き / スキップ / 連番）を一覧表示。R2 の対象確認モーダルに統合する

### 書き込み時
- 元ノートは書き換えない（設計原則）: .md・画像・.canvas は読み取り専用とし、書き込み系 API を呼ばない
- 同名ファイルの扱い: 上書き / スキップ / 連番（`name (1).docx`）を設定で選択
- アトミック書き込み: 一時ファイル（`.tmp`）に書き、完成後に rename で置き換える。失敗時に壊れた .docx / .xlsx を残さない
- 使用中ファイルの扱い: Word / Excel で開いているファイルへの書き込み失敗（Windows の `EBUSY` / `EPERM`）は、中断せずスキップしてレポートに記録
- 個人情報を出力に含めない（設計原則、2026-11-17 に後回しから格上げ）: 文書プロパティ（作成者・最終更新者）や埋め込むパスに、OS のユーザー名や Vault の絶対パスを入れない（C-8・D-5）

### 実行中
- 進捗表示: 「n / 全体件数」と処理中ファイル名を Notice またはステータスバーに表示
- エラー時の方針: continue-on-error（失敗しても次へ）/ fail-fast（その時点で停止）を設定で選択
- UI を固めない（2026-11-17 に後回しから MVP へ移動）: 1件ずつ逐次処理し、件ごとに `await` でイベントループへ制御を返す。一括変換が目標の中心で、Mermaid の描画に DOM を使うため
- キャンセル（同上で MVP へ移動）: 進捗表示に中断ボタンを置く。処理中の1件を終えてから止め、書きかけの一時ファイルを削除する
- 1件ごとのタイムアウト（同上で MVP へ移動）: `mermaid.render()` などのハング対策。既定 30 秒、超えたらその件を失敗として次へ進む

### 実行後
- 結果レポート: 成功・失敗・スキップ件数、未対応記法・リンク切れの警告を一覧表示
- 出力マニフェスト: 生成ファイルの一覧（出力パス・元ノート・内容ハッシュ・日時）を JSON で保存。後回し項目（手編集の検知、Undo、孤立ファイル掃除）や R2 の差分変換の土台にする

## R4. 画像の出力（確定）

R1 で生成する Mermaid 画像の品質と、Word への埋め込み方法を決める。

- ラスタ解像度（PNG）: DPI で指定する（既定 192 dpi = 2x 相当。印刷用プリセットでは 300 dpi）
  - `canvas` の幅と高さを `DPI / 96` 倍にして描画する
  - PNG の `pHYs` チャンクに解像度を書き込み、Word で開いたときの実寸を合わせる
- Word に貼るときのサイズ: 本文幅に収める
  - 本文幅 = 用紙幅 − 左右の余白（A4・余白 25mm なら約 16cm）。これより大きい図は縦横比を保ったまま縮小する
  - 最大高さも制限する（縦に長いシーケンス図への対策）
  - 小さい図は拡大しない
- Word への埋め込み形式: SVG ＋ PNG フォールバック
  - Word 2016 以降は SVG を表示し、古い環境ではフォールバックの PNG を表示する（`docx` ライブラリの `type: "svg"` + `fallback`）
  - 要検証: Word の中で SVG のテキストがどう描画されるか（フォントの代替）
- 配色: Mermaid テーマは `neutral` に固定し、背景は白で塗る
  - Obsidian の表示テーマ（ダーク等）には追従しない
  - 背景の透過は PNG だけで選べるオプションにする
- フォント: `fontFamily` を設定で指定する。既定は Windows と Mac の両方にある組み合わせ（例: `"Yu Gothic", "YuGothic", "Hiragino Sans", "Meiryo", sans-serif`）
- ファイル名とキャッシュ
  - 命名規則: 連番とハッシュを併用する `{ノート名}_mermaid_{連番2桁}_{ハッシュ8桁}.{svg|png}`
  - ハッシュ: SHA-256 の先頭8桁。入力は Mermaid ソースに加えて、描画結果を変える設定値（テーマ・フォント・DPI・背景）と mermaid.js のバージョン（2026-11-17 整理で追加: ソースだけだと設定変更後も古い画像が使い回されるため）
  - 差分レンダリング: 同じハッシュの画像が既にあれば描き直さずに使う
- 描画に失敗したとき: Word には Mermaid ソースをコードブロックとしてそのまま挿入し、結果レポート（R3）にも記録する
- キャプションと代替テキスト（設定で有効化、既定はオフ）
  - 図番号キャプション「図 n: ○○」。Word のキャプション機能（`SEQ` フィールド）を使い、図表目次も作れるようにする
  - キャプションの出どころ: Mermaid の frontmatter の `title`、なければ直前の見出し
  - 代替テキスト（alt text）: タイトル、なければ図の種類から自動で作る
  - 整理メモ: 図表番号は R4 のこの仕組みに一本化する（旧 C-4b・旧 H5 を統合）。表への「表 n」とすべての画像への適用は R6 の C-4b

## R5. ノート内の要素の変換（確定・2026-11-17）

旧「候補A」。各論点の推奨案で確定。中間表現の設計は G2、画像の解像度・フォールバック・命名は R4、Word 全体の体裁（スタイル・ページ設定・フォント）は R6、Excel 全体の体裁は R7 に従う。

### 前提
- A-0a 変換方式: ハイブリッド。文書構造は Markdown の構文木（mdast: remark + micromark 拡張で GFM・数式・Wikilink・コールアウトに対応）から生成し、Dataview・数式・他プラグインのコードブロックだけ Obsidian 側（`MarkdownRenderer.render()` など）で描画して取り込む
- A-0b 未対応・変換失敗: 原文を等幅のまま残し、結果レポートに警告を出す

### Word: ブロック要素
- A-1 見出し: 組み込みスタイル「見出し 1〜6」（`w:pStyle`）に1対1で対応させる。オプション: レベルを1段下げてファイル名を「表題」にする / 見出し番号を複数レベルのリスト（`w:numPr`）で付ける
- A-2 単一改行: Obsidian の「厳密な改行」設定に従う（オフなら段落内改行 `w:br`）
- A-3 リスト: Word の段落番号機能（`numbering.xml` の `w:abstractNum`、入れ子は `w:ilvl`）を使う。開始番号（`3.` 始まり）とリストごとの番号リセットに対応する
- A-4 タスク: 記号 ☐（U+2610）/ ☑（U+2611）。`[/]` `[-]` `[>]` などのカスタム状態は記号の対応表で変換する
- A-5 引用: 組み込みスタイル「引用文」
- A-6 コールアウト: 1行1列の表。左罫線を種類の色、背景を淡い色（`w:shd`）にし、先頭行に種類名とタイトルを置く。折りたたみ（`[!note]-`）は常に展開し、入れ子は表の入れ子にする。色は「既定色の固定表 / テーマの `--callout-color` を読む」を設定で選ぶ
- A-7 コードブロック: Prism（`loadPrism()`）でトークン化してシンタックスハイライトを付ける（`w:color`）。言語が不明なら等幅フォント＋網掛け。オプション: 行番号
- A-8 水平線 `---`: 段落の下罫線。`<div style="page-break-after: always"></div>` は改ページ（`w:br w:type="page"`）として扱う
- A-9 表: Word の表。見出し行を各ページで繰り返し（`w:tblHeader`）、列の揃え（`w:jc`）、セル内の書式と `<br>` を保持する。列幅は自動調整。罫線・網掛けは R6 の C-6
- A-10 脚注（`[^1]`、インライン脚注 `^[...]`）: Word の脚注（`w:footnoteReference`）
- A-11 数式（`$...$` / `$$...$$`）: Word のネイティブ数式（OMML: `m:oMath` / `m:oMathPara`）。LaTeX → MathML → OMML と変換する（MathJax または Temml と、`mathml2omml` などで実現。要検証）。変換に失敗した式は MathJax の SVG 出力で画像化する
- A-12 Mermaid: R1 のとおり画像で埋め込む。SVG を PNG の代替画像付き（`a:blip` + `asvg:svgBlip`）で埋め込む（要検証）

### Word: インライン要素
- A-13 文字書式: 太字 → `w:b`、斜体 → `w:i`、取り消し線 → `w:strike`、`==ハイライト==` → `w:highlight`（黄）、インラインコード → 等幅＋網掛けの文字スタイル
- A-14 インライン HTML: `<u>` `<sup>` `<sub>` `<mark>` `<br>` は対応する書式にし、それ以外のタグは除去してテキストだけ残す
- A-15 タグ `#tag`: テキストのまま残す
- A-16 コメント `%%…%%`: 削除する。オプション: Word のコメント（`w:comment`）として残す

### Word: リンク・埋め込み
- A-17 外部リンク・URL 直書き: ハイパーリンク（`w:hyperlink`）
- A-18 内部リンク（Wikilink・見出しリンク・別名付きリンク・`[text](note.md)`）: 単体出力では出力先 .docx への相対リンクにし、リンク先が変換対象外なら表示テキストのみにする。結合出力（C-8、ユーザー決定で v1 に採用）では文書内ブックマーク（`w:bookmarkStart` + `w:hyperlink w:anchor`）へのリンクにする。リンク切れはテキストのみ残してレポートで警告する。リンク先は `metadataCache.getFirstLinkpathDest()` で解決する
- A-19 ブロック ID `^id`: 本文から消し、その段落にブックマークを付ける。ブロック参照はそこへのリンクにする。ブックマーク名は Word の制約（40文字以内、英数字と `_`）に合わせて変換する
- A-20 画像: インライン図（`wp:inline`）として埋め込む。幅指定（`300`、`300x200`）は EMU に換算する（96 dpi で 1 px = 9,525 EMU）。幅指定がなければ本文の幅に縮める（R4 と同じ規則。小さい画像は拡大しない）。alt テキストは代替テキスト（`wp:docPr` の `descr`）にする。WebP など Word が対応しない形式は PNG に変換する。外部 URL の画像は既定ではリンクのみ（オプション: ダウンロードして埋め込む）
- A-21 ノート埋め込み `![[ノート]]`: 内容を展開する（トランスクルージョン）。`#見出し` の指定はその節だけ、`#^id` の指定はそのブロックだけを取り込む。循環参照を検出し、展開の深さに上限（例: 5）を設ける
- A-22 PDF・音声・動画: ファイル名のリンク。リンク先は元ファイルを指す `obsidian://open` URI（2026-11-17 整理で確定: ミラー出力で Vault 外に出すと相対パスが切れるため。添付ファイルのコピーは R8 で後回し）
- A-23 Canvas・Excalidraw: Excalidraw はプラグインが自動エクスポートした .svg / .png を使う。Canvas（JSON Canvas から自前で描画）は後回し

### 他プラグインの記法・メタデータ
- A-24 Dataview: Dataview API（`api.query()`）で結果を構造データ（見出しと行）として受け取り、Word の表にする（要検証）。`dataviewjs` は描画結果の HTML から取り込む。Dataview が入っていなければ A-0b のとおり原文を残して警告
- A-25 インラインフィールド `key:: value`: テキストのまま残す
- A-26 その他のプラグインのコードブロック（Tasks クエリ、Charts、PlantUML など）: Obsidian に描画させ、SVG か canvas が得られれば画像化する。得られなければ原文のまま残して警告を出す
- A-27 frontmatter: 文書プロパティ（`docProps/core.xml` の `dc:title`・`dc:creator`・`cp:keywords`・`dcterms:created`）とユーザー設定プロパティ（`docProps/custom.xml`）に入れる。どのキーをどのプロパティに入れるかは設定で変更できる。オプション: 冒頭にプロパティの表を出す

### Excel
- A-30 ノート本文の表し方: 既定では Markdown の表だけを抜き出す。オプション: アウトライン形式（見出しの階層を列「H1・H2・H3・本文」にし、1段落 / 1リスト項目 = 1行。行のグループ化で折りたためる）
- A-31 複数の表の置き方（2026-11-17 にユーザー決定 D-1b に合わせて既定を変更）: 既定は **1ノート = 1シート** で、ノート内の表を縦に並べる（表と表の間は空行で区切り、各表の前に直前の見出しを表題行として置く）。オプション: 1表 = 1シート
- A-32 セル内の書式: 太字・斜体・取り消し線はリッチテキストにする。ハイライトは文字単位で表せないので無視する。`<br>` はセル内の改行（折り返しを有効化）にする。リンクはセルのハイパーリンクにし、1セルに1つまでなので2つ目以降はテキストにする（旧 D-4 はこれに統合）
- A-33 画像・Mermaid・数式: 画像と Mermaid は PNG にしてセルに固定配置する（exceljs は SVG に非対応のため。要検証）。数式は LaTeX のまま
- A-34 Vault 全体の集計（出力するファイルの単位は R8）:
  - frontmatter の一覧: 1ノート = 1行で、Vault 全体を表にする
  - タスクの一覧: Vault 全体のタスクを集め、完了 / 未完了とノート名を列にする。Tasks プラグインの期日（📅）は日付型の列、優先度は別の列にする
  - Dataview のクエリ結果: そのまま Excel に出す
  - ノート名の列は、元ノート（`obsidian://`）か出力した .docx へのリンクにする

## R7. Excel の出力の質（確定・2026-11-17）

## R8. 出力の基本（確定・2026-11-17・Claude 推奨）
